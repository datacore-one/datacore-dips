# DIP-0050 implementation plan — evaluator audit, 2026-09-23

Six evaluators from `registry/evaluators.yaml` read the plan in full,
independently, read-only: critic, cto, coo, taleb, popper, data. Their reports
are recorded verbatim below as they arrived; the synthesis and the plan changes
it drives are at the end.

## taleb — risk (score 0.42, revise)

1. BLOCKER — Prompt-only rules. Every write path an agent can reach needs a code-enforced gate (schema validation, allowed-writer list); the plan fixes inbox and completion only — venture.yaml and scheduler configs are still prompt-policed.
2. BLOCKER — Reconciler blast radius is fleet-wide and un-canaried. A torn git pull or malformed venture.yaml reads as "cadences removed" and "mirror exactly" deletes real jobs on every host. No bound (refuse to remove >X% in one sync), no atomic-read guarantee.
3. MAJOR — No fleet-wide kill switch once hermes cron, OpenClaw and box cron run independently of the heartbeat.
4. MAJOR — No rollback for reconciler writes; scheduler state mutated in place, unversioned.
5. MAJOR — Shared quota is a common-mode failure; exhaustion presents as N unrelated late cadences instead of one root cause.
6. MAJOR — "Shards are the only input" is a promise, not a gate; no DONE_WHEN proves contamination is blocked.
7. MAJOR — Scheduling a fragile process turns a one-off destructive bug into a daily one; needs a circuit breaker (N anomalous runs auto-disable the job).
8. MINOR — `sync --check` reports drift but gates nothing.
9. MINOR — The induced-failure test exercises the old single point of failure, not the new distributed ones (bad venture.yaml, partial pull, quota exhaustion).
10. MINOR — Takeover (P3) has no anti-thrash bound.

## Synthesis

All six say **revise**. None disputes the model: the agent's own scheduler as executor, shards as the record, the box as judge. What they dispute is that the plan is safe to build as written. Grouped:

1. **Evidence and the judge** (critic 1, popper 2-3, taleb 1, cto 1). "A fresh file exists" is exactly what failed twice this morning. A completion counts only when (a) it names a cadence-specific result that follows a schema the box validates, not the actor, and (b) it is bound to a run record the scheduler wrote, not the agent. Freshness is commit time plus content hash, never mtime.
2. **Reconciler safety rails before any scheduler write** (taleb 2/4/8, cto 2/4/5/9, data 1, coo 6):
   - one canonical slug function shared by all four adapters (cron_install's KEY forbids `:`)
   - a lock protocol per scheduler (Hermes jobs.json with its ticker)
   - refuse on an unreadable or partial venture.yaml, and refuse to remove more than a bound per sync
   - diff-only writes
   - a versioned registration snapshot per sync, for rollback
   - an explicit logged `--adopt old=new` for the hand-made jobs
   - handoff on reassignment via the authorizing venture.yaml commit
   - `--check` drift that gates, not just reports
3. **Transition without double runs or manufactured reds** (critic 2, coo 2, data 4, critic 6):
   - the heartbeat excludes registered cadences, with its own work item and test
   - liveness enforces a role only once it has a registration record
   - a `reminder` state for human-owned cadences
4. **Fleet controls** (taleb 3/5/7, coo 1):
   - one pause flag that every adapter-generated job checks before running
   - a circuit breaker that disables a job after N anomalous runs
   - a daily budget per host in `plan` output
   - quota exhaustion reported as one root cause, not N late cadences
5. **Escalation, defined** (coo 3): the trigger, channel and threshold for agent → Winston → owner, plus a same-day failure signal. The git-replicated shards reach the box too late for that.
6. **Correctness gaps**:
   - schedules in UTC, with monthly day > 28 clamped to month end (data 5)
   - Data's dev.to mirror runs after the blog post (data 6)
   - discovery needs a space declaration on each host (critic 3; the DIP's claim was wrong)
   - liveness re-keyed by venture name (critic 4)
   - separate per-actor and all-actor functions (critic 5)
   - Winston's duties moved into venture.yaml as a work item (data 9)
   - an unassigned default fails loudly when that owner does not hold the space (data 2)
   - the readers of `owns.roles` migrated (critic 8)
   - the DIP's own prose normalized to venture names (data 3)
7. **DONE_WHENs that cannot lie** (popper 1/4/5, coo 4, taleb 9):
   - no hardcoded counts; recompute at check time
   - one induced failure per failure mode that motivated the DIP, plus the new ones (bad venture.yaml, torn pull, quota exhaustion)
   - soak one full period per frequency class
   - P1 asserts states, not a listing

**Consequence for the plan:** a new phase, **P1.5 — safety rails** (groups 2, 4 and the evidence schema from 1), goes in before any adapter writes to a live scheduler. P1 absorbs groups 3 and 6. Group 5 is designed with P1.5. The DONE_WHENs are rewritten per group 7. Winston's weekly plan is not blocked by any of this: its script fix shipped separately (chief-of-staff `a87520a`).
