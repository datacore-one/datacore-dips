# DIP-0050 implementation plan — evaluator audit, 2026-09-23

Six evaluators from `registry/evaluators.yaml` read the plan in full,
independently, read-only: critic, cto, coo, taleb, popper, data. Their reports
are recorded verbatim below as they arrived; the synthesis and the plan changes
it drives are at the end.

## taleb — risk (score 0.42, revise)

1. BLOCKER — Prompt-only rules. Every write path an agent can reach needs a code-enforced gate (schema validation, allowed-writer list); the plan fixes inbox and completion only — venture.yaml and scheduler configs are still prompt-policed.
2. BLOCKER — Reconciler blast radius is fleet-wide and un-canaried. A torn git pull or malformed venture.yaml reads as "cadences removed" and "mirror exactly" deletes real jobs on every host. No bound (refuse to remove >X% in one sync), no atomic-read guarantee.
3. MAJOR — No fleet-wide kill switch once hermes cron, OpenClaw and box cron run independently of the heartbeat.
4. MAJOR — No rollback for reconciler writes; scheduler state mutated in place, unversioned.
5. MAJOR — Shared quota is a common-mode failure; exhaustion presents as N unrelated late cadences instead of one root cause.
6. MAJOR — "Shards are the only input" is a promise, not a gate; no DONE_WHEN proves contamination is blocked.
7. MAJOR — Scheduling a fragile process turns a one-off destructive bug into a daily one; needs a circuit breaker (N anomalous runs auto-disable the job).
8. MINOR — `sync --check` reports drift but gates nothing.
9. MINOR — The induced-failure test exercises the old single point of failure, not the new distributed ones (bad venture.yaml, partial pull, quota exhaustion).
10. MINOR — Takeover (P3) has no anti-thrash bound.

## coo — operations

1. BLOCKER — Capacity: no budget math. The outage that triggered this DIP was the shared plan window; the plan adds ~23 + 3 + 3 + 4 runs/day to the same window with no ceiling, per-host budget or backoff. `plan` must carry estimated cost per cadence and daily draw per host; P2b gates on a stated ceiling with queueing.
2. BLOCKER — Day-1 flood: P1 makes Tris's cadences overdue while the working `geo-research-tris` job is only adopted in P2b — a manufactured red. Ship P1 with the Tris adoption, or enforce liveness per role only once it has a registration record.
3. BLOCKER — No escalation design: "agent -> Winston -> owner only when stuck" is not defined anywhere (trigger, channel, threshold); failures reach the box via git at up to a day's lag.
4. MAJOR — "3 days green" observes daily cadences only; weekly/monthly (40 of 62) cannot complete a cycle. Soak one period per frequency class, or say they roll out unverified.
5. MAJOR — New contracts must gate only on machine-graded exit codes, never manual review.
6. MAJOR — Adoption contradicts the reconciler's own rule (touches only `cadence:` jobs, yet must adopt `geo-research-tris` and seven `plur-daily-x-memory-*`). Needs an explicit, logged one-time `--adopt old=new`.
7. MAJOR — Original decision 2 (Winston's scope beyond firm:cos) is not closed in the 2026-09-23 decisions, but P2b step 4 assumes it.
8. MINOR — View/shard reconciliation has no owner or deadline; make it a P1 exit gate or real 6-meridian runs misreport as late.
9. MINOR — Data's tripled posting rides on an infra DIP with no check that fact-check/cos-approval can clear daily; soak the posting cadence separately.

## cto — technical (score 0.58, revise)

1. BLOCKER — Completion evidence (P2a-3) is nightshift-shaped end to end: `_KEYS` requires NIGHTSHIFT_STATUS/COMPLETED/OUTPUT (cadence_completion.py:25-26), `_task_evidence` reads only ledger/org DONE nodes (:29-49), `_artifact_metadata` requires `type: nightshift-output` (:108). The new path needs a real interface spec: what proves a Hermes/OpenClaw run happened, what "newer than window start" checks against.
2. BLOCKER — Hermes concurrency: "a spike checks first" is an investigation, not a design. Reconciler + ticker on one jobs.json need a locking protocol (the `file_lock` discipline cadence_store.py already uses) before rollout.
3. MAJOR — Cron derivation: no modulus, window bounds, collision tie-break, or consistent meaning of "day" (dow vs dom). Add a `plan` unit test that no two known cadences collide.
4. MAJOR — Ownership key across four key spaces: `cron_install.py` KEY `[a-z0-9][a-z0-9-]*` (cron_install.py:21) rejects colons; Hermes name, OpenClaw Declaration, schedules.yaml differ; names are free text. One canonical slug function shared by all adapters.
5. MAJOR — Removal/reassignment: no tombstone for renames, no handoff when `role.agent` moves hosts; independent reconcilers can double-run or drop. Explicit handoff or a documented gap.
6. MAJOR — `CadenceHistoryError` on ambiguous concurrent writes (cadence_store.py:157) propagates unhandled through `record_completion`; at 23-62+ runs/day it gets likelier. Define retry/page/drop.
7. MINOR (reuse) — Winston's adapter should call `cron_install.install()/reconcile()` with the `# datacore-job:` marker (cron_install.py:20-111).
8. MINOR (reuse) — `build_agent_prompt` is a thin delegate to `heartbeat_capture.context` (venture_heartbeat.py:258-261); say how the builder relates to `heartbeat_capture.enqueue`.
9. MINOR — No diff-only-on-change guard; frequent commits could churn scheduler entries.
10. MINOR — No schema-version on shards or the registration record; the named contracts are not specified.

## data — edge cases (score 0.62, revise)

1. BLOCKER — No reassignment / git-lag protocol in P1/P2: two hosts at different pull lag can both hold (double run) or neither hold (gap) a job. Use the registration record's venture.yaml commit: an old owner refuses to keep a job a newer commit reassigned; the new owner records the authorizing commit.
2. BLOCKER — Contradiction on the unassigned default: the model says "the space host's principal"; P1.1 hardcodes `miles` without checking miles's host holds the space — an orphaned cadence no reconciler schedules. `owner_of`/`venture_doctor` must fail loudly instead.
3. MAJOR — The DIP violates its own no-folder-numbers ruling in its own prose (the original decisions list and P2b step 3).
4. MAJOR — `human`-owned cadences are never registered, so the whole-upgrade DONE_WHEN ("0 not-registered") can never pass. Add a `reminder` state excluded from the count.
5. MAJOR — Monthly `d` > 28 skips months; no timezone pinned across four hosts; DST. All schedules in UTC; clamp day > 28 to month end.
6. MAJOR — Data's blog and dev.to mirror are unordered siblings; the mirror must follow the blog (and its fact-check). Model it as a follow-on step or add `after:`.
7. MINOR — A cadence deleted mid-run: its completion targets a role owner_of cannot resolve.
8. MINOR — A 3-day host outage and genuine neglect look the same to liveness; only neglect should ever trigger takeover.
9. MINOR — Winston's duties in `principals.yaml: owns.cadences` are never parsed by the reconciler; moving them to venture.yaml has no work item or DONE_WHEN.

## popper — falsifiability (score 0.42, revise)

1. BLOCKER — The cadence counts do not reproduce: 44 total by direct parse vs the plan's 62, and the plan's P2a DONE_WHEN hardcodes "56". *Checked by the author: both are true at their moment. 62 was the enabled ventures before 1-datafund and 3-fds were parked the same morning. 44 is all eight files after it, disabled ventures included. Now: 29 enabled, 23 of them Miles's non-continuous ones. The finding stands: a literal written into a DONE_WHEN went stale within hours.* Never hardcode; `plan --actor X` must equal a count recomputed from venture.yaml at check time. Induced test: add or remove a cadence and assert the count tracks it.
2. BLOCKER — The completion evidence proves a write, not that the duty was done. It passed "exists, non-empty, fresh" twice this morning. The actor names its own artifact. Needs a checkable claim about what was done (a result schema per cadence template, validated by liveness, not the actor). Induced test: a valid-shaped but content-free or wrong-field artifact must be marked failed.
3. MAJOR — mtime is not a stable proxy across git replication; use commit time (`git log -1 --format=%cI`) and a content hash against the prior entry.
4. MAJOR — The induced-failure test covers 1 of the 4 failure modes that motivated the DIP (config rejected, stale deploy, sense-phase TypeError, session window spent). One induced case per mode.
5. MAJOR — The P1 DONE_WHEN can be met cosmetically; assert state ∈ {late, not-registered} with days overdue, not just that the owner is listed.
6. MINOR — P0 drops the venture.yaml↔principals.yaml agreement test without a replacement check on `owner_of` alias resolution.
